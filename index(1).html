Title & Abstract

Title: Refresh Opportunity Scoring: Ranking Content for Review Using Age, Freshness, and Engagement Signals

Abstract: Content teams struggle to know which of thousands of pages are quietly losing search performance and deserve review. This project asks whether a page's age, update recency, and engagement signals can predict which pages are declining, well ahead of a full audit. Using an anonymized dataset of ~30,000 pages with 44–52 SEO and content features, a rule-based baseline score was first built from a simple decay heuristic, then compared against a Logistic Regression model trained on a wider feature set with proper imputation and encoding. The model outperformed the baseline on Precision@20 and Precision@50 under a random split, and the gain held up (though narrowed on Precision@50) under a stricter, client-grouped validation split designed to prevent leakage. The result is a ranked action list — Refresh Now, Monitor, or Leave As-Is — with a plain-language reason code attached to every page, giving content teams a defensible, explainable starting point for prioritization rather than a black-box score.

01

Introduction / Problem Statement

Search-facing content decays quietly. A page can keep ranking, keep receiving impressions, and still be losing clicks and engagement relative to its opportunity — long before anyone notices it needs attention. Content teams typically catch this only during periodic manual audits, by which point visibility has often already eroded.

The decision this work supports is a prioritization decision, not a content decision: given a limited content-review budget, which pages should a content team look at first? The guiding rule adopted for this lane was:

CORE HYPOTHESIS A page should be considered for refresh when it is old, still receives meaningful search visibility, and shows weak performance relative to its opportunity.

This paper turns that qualitative rule into a scored, ranked, and reason-coded output that a content team could act on directly.

02

Data

Release: Anonymized content and search performance dataset, FlyRank ML Internship Programme data warehouse (Hugging Face, gated access).

Scale: ~30,000 rows. The initial exploration used 44 columns; after feature preparation for modeling, the working feature vector (refresh_feature_vector.csv) expanded to 52 columns.

Key fields used: impressions_90d, clicks_90d, sessions_90d, content_age_days, days_since_last_update, ctr, avg_position, trend_direction, plus derived log-scaled traffic features and tiered categorical bands (age, freshness, word count, impressions, position).

Target construction: is_declining_label was derived from trend_direction == "down", producing a distribution of 16,262 declining pages vs. 13,738 not declining — a reasonably balanced target, not a rare-event problem.

Exclusions: No client names, domains, URLs, private queries, credentials, or raw exports are included anywhere in this paper, the underlying notebooks, or the released repository, per the dataset's public-use terms.

03

Methodology

Assumptions

The core assumption is that trend_direction == "down" is a reasonable proxy for "declining performance," and that a page's age, update recency, and current engagement carry enough signal to anticipate that state before a manual review would catch it. This is treated as an associative, decision-support signal — not a causal claim about why any individual page declined.

Features

Numerical: search_volume, competition, cpc, word_count, char_count, log_impressions_90d, log_clicks_90d, log_sessions_90d, log_ai_sessions_90d, days_with_impressions, days_with_sessions, content_age_days, days_since_last_update, ctr, avg_position, engagement_rate, scroll_rate, ai_traffic_pct.

Categorical: competition_level, content_type, main_intent, age_tier, freshness_tier, word_count_tier, impression_tier, position_tier.

Preprocessing: median imputation for numerical features, most-frequent imputation for categorical features, one-hot encoding for categorical variables.

Label definition

is_declining_label = 1 where trend_direction == "down", else 0.

Baseline

A rule-based baseline action score was built first (Week 4), directly encoding the age × visibility × weak-performance hypothesis above, without machine learning. This baseline is the bar the model needs to clear — a model that only matches a simple rule is not adding value.

Model

Logistic Regression was chosen over a more complex classifier for interpretability: content teams need to trust and explain why a page was flagged, and coefficient-based reasoning supports the reason-code output described in Section 06.

Validation design

Two validation strategies were run deliberately, not just one, because a random split can overstate performance when pages from the same client or property share underlying patterns:

  • Random split — standard train/test split, no grouping constraint.
  • Grouped split (by client) — enforces that no client appears in both train and test, giving a stricter, more honest estimate of how the model generalizes to genuinely unseen content.

Leakage checks

Before trusting either validation run, the feature set was audited to confirm no forbidden or label-derived columns were included — specifically, nothing that encodes trend_direction or a post-outcome signal was allowed into the feature matrix. No leakage was found.

Two things stand out. First, the model beats the baseline on every run — the gain is not an artifact of one lucky split. Second, Precision@50 is sensitive to validation design: it drops from 0.80 (random split) to 0.74 (grouped split by client), while Precision@20 holds steady at 0.75 across both. This is treated as the honest number: the grouped-split result (P@20: 0.75, P@50: 0.74) is the one used for all downstream claims in this paper, since it best simulates performance on genuinely unseen content.

The direction of these coefficients is broadly consistent with intuition rather than the original age-driven hypothesis specifically: engagement quality (CTR, sessions, top ranking positions) pulls a page away from "declining," while raw impression volume alone does not protect a page — a page can still be losing ground even while accumulating visibility, which is exactly the quiet-decay pattern this project set out to catch. Notably, content_age_days and days_since_last_update did not surface among the strongest coefficients, suggesting engagement signals carry more weight in this model than staleness alone — a useful refinement to the Week 3 hypothesis rather than a contradiction of it.

False positives tended to involve pages with a very low or zero CTR, or a recent update — cases where a single weak signal (e.g. CTR = 0.00) was enough to push the predicted probability up even though the page had just been touched. False negatives clustered around low-visibility pages with only a handful of impressions, where the model likely lacked enough signal to distinguish genuine decline from sparse data. These examples are illustrative of error patterns, not proof of why the model made any individual prediction.

05

Limitations & Honest Framing

This model identifies pages associated with decline — it does not establish, and does not claim to establish, that any specific factor causes decline, or that refreshing a flagged page will reverse it. Two methodology questions surfaced during review (Week 6) sharpen this point:

  • Are refreshed and non-refreshed pages truly comparable, or were refreshed pages already stronger or more strategically important to begin with? Without a controlled comparison, an observed link between refreshing and improved performance could simply reflect which pages got attention in the first place.
  • Do observational results of this kind establish that refreshing causes improvement, or only that refreshed and improved tend to co-occur? This paper treats them as the latter.

Consistent with this, language throughout this paper is kept to observed, directional, and decision-support terms rather than causal or algorithm-revealing claims. No claim here should be read as describing or proving how Google's ranking algorithm works.

Precision@50 dropped meaningfully between the random and grouped validation split (0.80 → 0.74), while Precision@20 did not. This means the model's top-tier judgments are more stable than its judgments further down the ranked list — a caveat worth surfacing to anyone using this output at scale rather than just skimming the top of the list.

06

Ranked Recommendations — Action Playbook

Rather than returning a raw probability, the model output is translated into three action tiers, each carrying a short, human-readable reason code built from the page's own signals — this is what turns a classifier into a usable action engine.

Refresh Now

High decline probability, combined with real content age and meaningful residual visibility — the page matches the core hypothesis (old + visible + underperforming) closely.

content_age: high days_since_update: high ctr: below median
Monitor

Moderate decline probability, or a page that was recently updated but still shows early softening — not urgent, but worth a check next cycle rather than immediate rewrite.

decline_prob: mid days_since_update: low
Leave As-Is

Low decline probability with stable or strong engagement — reviewing this page would spend budget better used elsewhere.

decline_prob: low engagement_rate: healthy

In practice, the final ranked CSV sorts all pages by decline probability within each tier, so a content team works strictly top-down inside "Refresh Now" first, using the attached reason codes to decide what kind of refresh (rewrite vs. metadata fix vs. consolidation) each page likely needs.
